## 3. Work list (in order)

**1. ci-local never repoints Mark's venv from a worktree.**
`scripts/ci-local.sh` with `PYTHON` unset defaults to `/home/mark/tahoe-venv` and runs `pip install -e .`. From a worktree, that repoints Mark's venv at the worktree. Fix: when `PYTHON` is unset and the script runs from a linked git worktree (`git rev-parse --git-dir` differs from `--git-common-dir`), do not use `/home/mark/tahoe-venv`. Use `$ROOT/.venv/bin/python`, creating it with `python3 -m venv` if it is missing. Echo which interpreter it chose and why. Add `CI_LOCAL_PRINT_PYTHON=1` (print the chosen interpreter and exit 0) so tests can run without installing.
DoD: a pytest that runs the script under bash in a temp linked worktree with `CI_LOCAL_PRINT_PYTHON=1` gets the worktree `.venv` path, never the tahoe-venv path. An explicit `PYTHON=` is still honored. Behavior in the main checkout is unchanged. Note the new knob in the CONTRIBUTING or AGENTS verify section (one line).

**2. Shutdown leaves no orphan or zombie Tahoe / Magic Folder process.**
`TahoeCtl.stop` and `MagicFolderCtl.stop` (`backend.py`, around lines 1035 and 1428) call `kill()` after a terminate timeout but never wait on the process again, and a broad `except Exception` hides errors. Fix: after `kill()`, `wait()` with a short bound. Catch only `subprocess.TimeoutExpired` / `OSError`. `stop()` must be safe to call twice and when the process already exited.
DoD: a test starts a real child Python process that ignores SIGTERM (with the terminate wait shortened through a parameter or module constant, not a sleep of 10s), calls `stop()`, and asserts the PID is gone and reaped (`proc.poll() is not None`). A second `stop()` is a no-op. Skip on Windows only if the signal can't be ignored there.

**3. sync-ui.log can't grow without bound.**
`log_exception` (`app.py`) appends to `logs/sync-ui.log` forever. Fix: before writing, if the file is over 1 MiB, rotate it to `sync-ui.log.1`, replacing any older `.1`. Rotation failure (read-only dir, file locked) must not raise or lose the new entry if the file itself can still be appended.
DoD: tests cover rotation at the size limit, keeping only one backup, and a rotation failure that still writes the entry and never raises. Mention `sync-ui.log.1` in the TESTER-GUIDE logs paragraph (a few words).

**4. Only one Sync window per Sync home.**
A second launch on the same Sync home starts a second Tahoe / Magic Folder on the same node dir. Fix: take a lock in the Sync home at startup (`QLockFile` or an equivalent pid lock, with stale-lock recovery). If another live instance holds it, show one plain dialog: "Leasegrid Sync is already running. Use the open window." Then exit with status 0 without starting Tahoe. A stale lock (dead PID or crash) is taken over silently. CLI subcommands that don't start daemons are not blocked.
DoD: tests prove a second instance on the same home is refused and starts no daemon, a different `LEASEGRID_SYNC_HOME` is not blocked, and a stale lock left by a killed process is recovered. Use a real second process or a real lock file, not a mock of the lock.
