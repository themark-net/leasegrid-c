## 3. Work list (in order)

**1. (B3, MUST) A corrupted geometry file never stops the app.**
- `_saved_frame()` (`src/leasegrid_sync/app.py`) computes width as `right - left + 1` with no range check.
- `_restore_window_geometry()` then builds `QRect(*saved)` outside its `try`.
- Flipping one bit (the sign of the saved frame's left edge) gives `OverflowError: argument 3 overflowed` on every launch. A frame of `(0, 0, 2^31-1, 2^31-1)` fails the same way.

Fix:
- Range-check every decoded value in `_saved_frame`: coordinates within ±2^30, width and height in `1..QWIDGETSIZE_MAX (16777215)` and also ≤ 2^30. Out of range returns `None`.
- Wrap the WHOLE restore (decode, frame check, `QRect`, `restoreGeometry`, screen checks) in `try/except Exception` that falls back to the default geometry (and logs once via `log_exception`).
- The default must still apply cleanly after a partial failure.

DoD:
- (a) A test that saves a real blob from a real `MainWindow`, flips the sign bit of the frame-left field, and starts a new window. It opens at the default size with no exception. Locate the field from the documented layout used by `_saved_frame`, not a magic offset.
- (b) The same through a **real launch**: a subprocess running the app entry (like `tests/test_sync_instance_lock.py`'s driver) with that corrupted file. It shows the window and exits 0.
- (c) The `(0, 0, 2^31-1, 2^31-1)` frame falls back too.
- Mutations: drop the range check, and drop the outer `try`. Each must turn some test RED. (With both the range check and the try present, removing just one may leave the other guarding. Log which tests catch which, and make sure at least one test catches each guard alone. For example, a test that calls `_saved_frame` on the flipped blob and expects `None` catches the range check.)
- Correct the handoff and code comment "Any parse failure keeps the default" so they are true.
