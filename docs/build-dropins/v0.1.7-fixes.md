## 3. Work list

**1. B1 (security): the `--join` handoff must never send the invite to a squatter.**

Reviewer's finding:
- `hand_join_invite` sends before any lock check.
- It connects to the predictable `tempfile.gettempdir()/leasegrid-sync-<sha256(home)[:32]>` in world-shared /tmp, with no owner, socket-type or mode check.
- A foreign AF_UNIX listener there receives the invite. The CLI returns 0 and nothing is joined.
- A Windows named pipe can be squatted the same way.

Required:
- (1) **Lock gate first.** Call `_lock_is_held(home)` before anything else. If it's false, return `"free"` with no connect attempt, so the normal join runs. Only when it's true, try the handoff: `"sent"` on success, else `"busy"`.
- (2) **Private endpoint on POSIX.**
  - The server listens on an **absolute** socket path inside a per-user dir with mode 0700. Use `<Sync home>/run/` when the full path fits; otherwise use `$XDG_RUNTIME_DIR/leasegrid-sync/`.
  - The AF_UNIX path limit is about 104 bytes on macOS and 108 on Linux; check the encoded length is under 100. If it doesn't fit, fall back to a 0700 dir named `leasegrid-sync-<uid>` under `$TMPDIR` (or `tempfile.gettempdir()`), holding a hashed socket name. Put the shared path-choosing logic in one helper used by both client and server.
  - Create the dir with mode 0700. If it already exists, lstat it: it must be a real dir (not a symlink), owned by `os.getuid()`, with mode `& 0o077 == 0`. Otherwise refuse: log a note without the invite, and never chmod or reuse someone else's dir. On the server side, don't listen; the window still works.
  - **Client, before connecting:**
    - lstat the parent dir and apply the same checks;
    - lstat the socket: `stat.S_ISSOCK` and `st_uid == os.getuid()`.
    - Any failure means no connect, and the result is `"busy"`.
  - **Server:** `QLocalServer.listen(<absolute path>)` after removing only a stale socket file that we own, inside our own private dir. Set `setSocketOptions(QLocalServer.UserAccessOption)` too.
- (3) **Windows:** set `QLocalServer.UserAccessOption` before `listen`, so the pipe is user-only. Keep the lock gate in front. In the helper, there's no portable way to verify the pipe owner from the client, so note in the handoff that the lock gate plus the user-only ACL is the defense.
- Remove the old `_join_socket_path` (the gettempdir name) and any reference to it.

Fail-path tests. Each one starts with a planted fake invite and asserts the listener received 0 bytes.
- (a) **Old-path squatter.** No Sync running, the lock is free, and a foreign AF_UNIX listener sits at the OLD `/tmp/leasegrid-sync-<hash>` path. `hand_join_invite` returns `"free"`, and the listener's `accept()` never fires.
  - Mutant: send before the lock check (the old order) → RED.
- (b) **Free lock, no connect.** Monkeypatch or spy `socket.socket.connect` (and the Windows helper `subprocess.run`), and assert neither is called when the lock is free.
  - Mutant: drop the lock gate → RED.
- (c) **Bad dir, POSIX.** The lock is held by a real process, or a helper process holding the QLockFile.
  - (c1) The private dir has mode 0755: refused, the listener gets nothing, and the result is `"busy"`. Mutant: skip the mode check → RED.
  - (c2) The private dir is a symlink to a dir we own: refused. Mutant: `stat` instead of `lstat` → RED.
  - (c3) A wrong owner can't be made without root. Inject the uid check through the helper with a fake `os.getuid()` returning a different uid, and assert refusal. Mutant: skip the uid check → RED.
- (d) **Non-socket at the path.** A regular file or FIFO at the socket path is refused. Mutant: skip `S_ISSOCK` → RED.
- (e) **Happy path still works.** The existing real two-process test still passes: process 2 exits 0, and process 1's field holds the invite.
- (f) **Long-home fallback.** A Sync home whose path makes the socket path longer than 100 bytes still hands off. Use a deep tmp dir with a real two-process run or a direct server+client in one process. Mutant: no fallback → RED. On macOS CI, `$TMPDIR` is long, so this is the realistic case.
- (g) **Windows: the server uses UserAccessOption.** Assert that the option is set, through a sociable check of `server.socketOptions()`. Mutant: the option is removed → RED.
