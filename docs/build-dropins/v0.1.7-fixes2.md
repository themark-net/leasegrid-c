**2. (T3 blocker) The empty-lock fast path breaks mutual exclusion.**
`acquire_instance_lock` removes any lock whose PID it can't read, including a rival's brand-new lock. With 6 concurrent callers, 2–9 per 1000 trials end with double holders; b4e9b70 had 0/1000. Repro: `tmp/pr74-evidence/live/lock_race.py`.
- Fix: never remove a PID-less lock that is younger than a short age threshold (for example 2 s by the file's mtime, via `QFileInfo` or `os.stat`). Younger → refuse ("already running"); the user retries. Older and still PID-less → remove and retry once.
- Keep the `_lock_writer_grace` re-check.
- An atomic rename/link protocol is also acceptable if it is simpler and proven. Log the choice.
- Reviewer's original nit, a crash mid-write blocking relaunch for 30 s, is now bounded by the threshold: say so in the handoff.
- DoD:
  - A race test: real processes or threads (≥6) calling `acquire_instance_lock` on one home simultaneously, for enough rounds to catch it in CI time (at least 200 rounds, under 60 s). Assert 0 double holders, with each round's holders checked while all are still holding.
  - Run Tester's `lock_race.py` (or an equivalent) for 1000 trials locally: 0 double holders, logged.
  - Existing tests still pass: empty/garbage lock older than the threshold relaunches; fresh empty lock refused; live holder refused; 6-way start.
  - Mutant: remove the age check → the race test (or a direct fresh-empty-lock test) RED.

**3. (T4 blocker) `reap_child` killpg's a stale group.**
`stop()`/`reap_child` in `src/leasegrid_sync/backend.py` calls `os.killpg` for a daemon whose leader `poll()` has already reaped, and so SIGKILLed an unrelated process group (pid reuse). Repro: `tmp/pr74-evidence/live/pg/reap_stale.py`.
- Fix: check `proc.poll()` (or `returncode`) before **every** group signal. Once the leader is reaped, never signal its pgid again.
- Signal the group only while the leader is unreaped (a zombie leader still pins the pgid). Kill grandchildren first, while the leader is alive; then wait.
- Same on Windows: no `taskkill /T` after the process has exited.
- DoD:
  - A test that `stop()` on an already-exited and reaped child sends no signal: spy on `os.killpg` and `os.kill`. On Windows, spy on the `subprocess.run` taskkill call.
  - A test simulating pid reuse, adapting Tester's repro: a reaped daemon whose pgid now belongs to an unrelated test process; that process survives.
  - The existing grandchild-kill test still passes.
  - Mutant: drop the liveness check → RED.
