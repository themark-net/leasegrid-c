### What this branch added

1. **Join failure copy no longer tells a person to paste a raw introducer furl.** A garbled code, and a pasted web URL, used to end with “or a `pb://` furl”. They now say to ask for a fresh short code like `7-word-word`, or a join link. A furl that is already `pb://` still parses. The storage-server paste path is unchanged.
2. **The share QR is a normal three-finder symbol, drawn at its own size.** `qr_png` / `qr_svg` pass `micro=False`, so a short code is not a Micro QR. The widget no longer scales the image to 160px, which is not a whole number of modules.
3. **Behavior tests** in `tests/test_sync_invite.py` and `tests/test_sync_ui.py`, with a pixel decoder in `tests/qr_decode.py` (no libzbar, no new dependency):
   - Code generation from a Tahoe stand-in’s `Invite Code for client:` line, then join with that code (`--join=`, not `--introducer`).
   - QR payload decoded from the PNG bytes and from a grab of the share dialog as rendered (`widget.grab()`), not from `qr.pixmap()`.
   - Copy puts that same code on the clipboard, not a furl and not the join URL.
   - Fail, then recover, on one joiner: garbled text, a rejected code, an expired/lonely code (`0-dead-code`), then the live code connects and clears the error. The invite process is still alive for that last join.
4. Operator note in `docs/modules/leasegrid-sync.md`: a garbage invite, and a pasted web URL, are recovered with a short code or join link. The table no longer tells the operator to paste an introducer furl for those two failures.
